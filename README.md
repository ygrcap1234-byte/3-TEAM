## 소개

**코코단**은 2026학년도 2학기 「AI와 스타트업 문제해결」 3팀의 팀 이름입니다. 로켓단 패러디 컨셉으로, "평범한 팀 소개 페이지를 점령한 침입자 3인"이 직접 자기소개를 하는 팀 페이지와 정체 공개 영상을 만들었습니다.

프로젝트는 **AI를 활용해 실제 사용자의 문제를 찾고, 작게 만들고, 빠르게 검증하는 스타트업형 팀 프로젝트**입니다. 구체적인 주제는 사용자 인터뷰 결과를 보고 확정합니다.

| 키워드 | 설명 |
|---|---|
| 문제 중심 | 기술이 아니라 사용자의 문제에서 출발합니다 |
| 작게, 빠르게 | 1주 스프린트로 만들고 검증합니다 |
| 투명한 협업 | 모든 작업은 이슈로 남기고 칸반 보드에서 공유합니다 |

## 프로젝트

**주제: 선정 중.** 킥오프 회의에서 나온 후보를 두고 각자 사용자 문제를 조사한 뒤 확정합니다.

- [ ] 후보 A: 대학생 일상 문제 해결형 AI 서비스
- [ ] 후보 B: 소상공인 업무 자동화 도우미
- [ ] 후보 C: 팀 자체 아이디어 (브레인스토밍)

주제가 확정되면 이 자리에 **해결하려는 문제 · 대상 사용자 · 핵심 기능**을 채웁니다.


## 일하는 방식

수업에서 배운 애자일 요소를 그대로 팀 운영에 적용합니다.

- **스프린트**: 1주 단위. 매주 화요일 수업 시간에 리뷰와 회고(Pursue · Pivot · Pause)를 합니다.
- **칸반 보드**: GitHub Projects. 컬럼은 `Backlog → Ready → In progress → Done`.
- **이슈**: 모든 작업은 마크다운 이슈로 등록하고 마일스톤을 지정합니다. 형식은 [이슈 템플릿](.github/ISSUE_TEMPLATE/task.md)을 따릅니다.
- **Daily Scrum**: 슬랙 채널에 "어제 한 일 / 오늘 할 일 / 막힌 것" 세 줄로 공유합니다.
- **회의록**: [`회의록/`](./회의록) 폴더에 날짜별로 남기고, 마지막에는 반드시 담당자와 기한이 있는 **Next step**을 적습니다.

## 협업 규칙

- **브랜치**: `main`은 항상 배포 가능한 상태로 유지합니다. 작업은 `feat/기능명`, `fix/버그명`, `docs/문서명` 브랜치에서 합니다.
- **커밋 메시지**: `타입: 내용` 형식. 타입은 `feat`, `fix`, `docs`, `style`, `chore` 중 하나입니다.
- **Pull Request**: `main`에 합칠 때는 PR을 열고 팀원 1명 이상의 확인을 받습니다.
- **이슈 연결**: 커밋이나 PR 본문에 `#이슈번호`를 적어 이슈와 연결합니다.
